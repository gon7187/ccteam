# Браузер папок в Telegram-боте: выбор и создание проекта через файловую систему

> Дата: 2026-09-02 · Статус: owner одобрил вариант 1 в чате · Красные линии §三 не задеты: движок не вызывает LLM, ничего не инжектит, файлы проекта пишет только тот же `bootstrap_project_at_dir`, что и `/newproject`.

## 1. Проблема

Выбор проекта в боте сегодня это плоский ряд кнопок `cmd:/cd <slug>` из `render_projects`. Owner заходит в проект мысля папками, а не слагами, и хочет видеть в боте дерево каталогов, как в терминале, с возможностью сделать любую папку проектом на месте.

## 2. Область

- Команды `/projects` и `/cd` без аргумента для оператора открывают браузер каталогов, корень `projects_root` (`/root/projects`).
- Навигация только вниз от корня и обратно, выше корня нельзя.
- Выбор папки: зарегистрированная переключает текущий проект чата, незарегистрированная после подтверждения проходит тот же путь, что `/newproject`, и становится текущей.

**Не в области**: показ файлов внутри папок, веб-консоль, персистенция позиции в дереве между рестартами, изменение существующего `/newproject <slug> <path>`, tenant и guest (им остаётся старый список).

## 3. Модель

### 3.1 Чистый модуль `crates/ccteam-im/src/fs_browser.rs`

```rust
pub struct Entry { pub name: String, pub slug: Option<String> }
pub struct Page { pub rel: PathBuf, pub entries: Vec<Entry>, pub page: usize, pub pages: usize }

pub fn list(root: &Path, rel: &Path, registered: &[(String, PathBuf)], page: usize) -> Result<Page>;
pub fn resolve(root: &Path, rel: &Path) -> Result<PathBuf>;
```

- `resolve` собирает `root/rel`, канонизирует обе стороны и требует, чтобы канонический результат лежал под каноническим корнем. Симлинк наружу или `..` дают ошибку. Корень `/root/projects` сам доступен через симлинк `/home/gon71/projects`, поэтому сравнение идёт только по каноническим путям.
- `list` читает каталог, оставляет только каталоги, выбрасывает имена с точкой в начале, `node_modules`, `target`, `__pycache__`. Сортировка: сначала папки, для которых нашёлся `slug` (канонический путь папки совпадает с каноническим `path` записи `config.yaml`), внутри группы по имени. Страница 8 записей, `pages` не меньше 1.
- Модуль не знает про Telegram и gateway, тесты гоняются на tempdir.

### 3.2 Состояние в gateway

`fs_nav: BTreeMap<ChatKey, FsNav { rel: PathBuf, page: usize }>` в памяти. Пропадает при рестарте демона, при следующем `/projects` начинаем с корня.

### 3.3 Callback-протокол

Лимит Telegram на `callback_data` 64 байта, пути в него не кладём. Кнопки несут только индексы внутри текущей страницы:

| data | действие |
|---|---|
| `nav:fs:i:<n>` | войти в n-ю папку текущей страницы |
| `nav:fs:pick:<n>` | переключиться в n-ю папку страницы (она уже проект) |
| `nav:fs:up` | на уровень выше, в корне не показывается |
| `nav:fs:pg:<n>` | переключить страницу |
| `nav:fs:here` | выбрать текущую папку: проект → переключение, иначе confirm и создание |

Префикс `nav:` уже разбирается в `resolve_nav_selection`, семейство `fs:` добавляется туда же.

Индекс проверяется против свежего `list` в момент нажатия. Если содержимое каталога поменялось и индекс не совпал, бот перерисовывает страницу и просит нажать ещё раз, ничего не делает вслепую.

### 3.4 Выбор папки

- Папка зарегистрирована (по каноническому пути) → `change_project(chat, slug)`, ответ как у `/cd`.
- Папка не зарегистрирована → тот же гейт подтверждения, что у `cmd:?` (gateway-held токен, кнопки `cmd:!<token>` / `cmd:x<token>`), с текстом «Сделать проектом `<abs path>`?». Полный путь в `callback_data` не кладётся, он живёт в токене на стороне gateway. После «да»: `pick_unused_project_slug(ccteam_root, slugify(имя папки))` → `bootstrap_project_at_dir(paths, abs, slug, "(created from IM fs browser)", "dev")` → owner в `state.json` через `canonical_owner(chat)` → `upsert_project` в `config.yaml` → `register_project` → `change_project`. Это буквально тело `/newproject`, оно выносится в общий метод `create_project_at(chat, slug, abs)`, а `/newproject` зовёт его же.
- Корень `/root/projects` сам по себе выбрать нельзя, `nav:fs:here` в корне не рендерится и отклоняется.
- В зарегистрированную папку нельзя войти как в каталог, её строка ведёт только на переключение. Проект внутри проекта заводится через `/newproject`, это не задача браузера.

### 3.5 Вид (Telegram Rich Messages, Bot API 10.3)

Сообщение редактируется на месте, как список сессий. **Одна строка = одна папка, кнопка справа в той же строке** через инлайновый `<tg-button type="callback_data" style="link">` внутри параграфа (RichTextButton), не блочный ряд под строкой. Строки:

- `✅ <name>` для папки, которая уже проект, кнопка справа `Переключиться` → `nav:fs:pick:<n>`;
- `📁 <name>` для обычной папки, кнопка справа `Открыть` → `nav:fs:i:<n>`.

Заголовок: `📂 /root/projects/<rel>` и `страница k/n`, если страниц больше одной. Нижний блочный ряд `<tg-button-row>`: `⬆️ Вверх` (не в корне), `◀` / `▶` (если страниц больше одной), `📌 Сделать проектом` (не в корне, текущая папка не зарегистрирована) или `💬 Переключиться` (текущая папка уже проект). Индекс `<n>` в `nav:fs:*` это позиция на текущей странице.

Макет в терминале:

```
📂 /root/projects
страница 1/6

✅ 4g                              Переключиться
✅ ccteam                          Переключиться
✅ dashigor                        Переключиться
📁 DASHIGOR-trial                        Открыть
📁 RKN                                   Открыть
📁 TestPonytail                          Открыть
📁 WB_ADW_SKILL                          Открыть
📁 YIT                                   Открыть

[ ◀ ] [ ▶ ]
```

```
📂 /root/projects/ccteam-wt

📁 dev                                   Открыть
📁 fs-browser                            Открыть

[ ⬆️ Вверх ] [ 📌 Сделать проектом ]
```

Classic-фолбэк (rich выключен circuit breaker-ом): `telegram_html::strip_rich_button_rows` дополнительно вырезает инлайновые `<tg-button>…</tg-button>`, а те же кнопки уезжают в `button_rows` как обычная inline-клавиатура под сообщением, по одной кнопке в ряд с именем папки в подписи. Web-чат получает `plain` без тегов.

### 3.6 ACL

Браузер открывается только для `Principal::Operator`. Tenant и Guest на `/projects` получают прежний `render_projects` по видимым проектам. Callback `fs:*` от не-оператора отвечает «недоступно» и ничего не читает с диска. Это защита содержимого ФС, не замена `can_see_project`: переключение в зарегистрированный проект всё равно проходит через `change_project` с его проверками.

### 3.7 Ошибки

- Нет прав на чтение каталога → страница с текстом ошибки и кнопкой `⬆️ вверх`.
- `bootstrap_project_at_dir` упал (обычно права на запись) → читаемая ошибка с абсолютным путём, никакой подчистки, `config.yaml` не тронут, потому что регистрация идёт после успешного bootstrap.
- Путь вышел за корень (симлинк, гонка с переименованием) → «папка недоступна», состояние `fs_nav` сбрасывается в корень.

## 4. Тесты

- `fs_browser`: фильтр скрытых и служебных, только каталоги, пометка зарегистрированных по каноническому пути, сортировка, пагинация по 8, `resolve` отбрасывает `..` и симлинк наружу, корень через симлинк работает.
- `im_views`: строка папки содержит инлайновый `<tg-button>` с нужным `data`, `button_rows` фолбэка совпадают по данным; `telegram_html` вырезает инлайновые кнопки в classic.
- gateway с фейковым ботом: `/projects` от оператора рисует корень; `nav:fs:i` входит и меняет `fs_nav`; `nav:fs:pick` переключает проект; `nav:fs:here` на незарегистрированной ведёт в confirm, после подтверждения проект создан, зарегистрирован в `config.yaml`, стал текущим; `nav:fs:*` от tenant отклоняется; протухший индекс не выполняет действие.
- `/newproject` после выноса общего метода проходит свои старые тесты без изменений.

## 5. Файлы

- новый `crates/ccteam-im/src/fs_browser.rs`, подключение в `lib.rs`;
- `crates/ccteam-im/src/gateway.rs`: обработчики `/projects`, `/cd`, ветка `fs:` в разборе callback рядом с `resolve_nav_selection`, метод `create_project_at`, поле `fs_nav`;
- `crates/ccteam-im/src/im_views.rs`: рендер страницы браузера (инлайновые `<tg-button>` в строках, блочный ряд навигации, `button_rows` для фолбэка);
- `crates/ccteam-im/src/telegram_html.rs`: вырезание инлайновых `<tg-button>` в classic-фолбэке;
- `docs/usage.md`: абзац про `/projects` как браузер папок для оператора.

## 6. Права на `/root/projects`

Каталог принадлежит root с ACL, демон работает от `gon71`. Чтение работает уже сейчас. Создание проекта в папке без права записи упадёт на bootstrap с читаемой ошибкой, права выдаёт owner по факту, движок их не меняет.
